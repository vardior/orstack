# Evidence for finalize Step 1

## Lower tiers

The lower tiers exist for diffs that genuinely have no fuller surface: for a diff with **no runtime surface** (a pure function, a test-only PR), an executed old-vs-new differential — both versions run over the same inputs, the difference recorded — or a fault injected into the production code path that the change is supposed to catch; the **rendered artifact** (the built OpenAPI document, the generated PR body, a screenshot of the rendered string) for diffs that touch no control flow; a **running process** when behavior changed; the **full flow** when an integration or persistence boundary changed. At every tier, a mock of the production path does not count as real. The harness that produced a differential or a measurement is evidence, not a deliverable: it stays in the bundle and out of the diff, and a test is committed only when it pins behavior of our own code. Name the surface and why in the `## For the PR` block so the reviewer can disagree.

## The bundle

The output is an **evidence bundle** in the verify skill's durable evidence directory, or — when no verify skill applies — in a durable per-repo directory you create for it, `~/<repo>-verify/evidence/<slug>/`. Never `/tmp` or a session scratchpad. The bundle is: `EVIDENCE.md` with a SHA header, a scenario table (driven → observed → evidence file), the raw artifacts, and a `## For the PR` block written for the reviewer, short enough that `visual-pr` can lift it verbatim: one plain sentence naming the surface that was driven and why it is the right one for this diff, then driven → observed in the reviewer's vocabulary as a two-column `| Driven | Observed |` table. Every count and number lives in that table, never in prose; builds and unit tests are one row at most. No `Verification tier:` label. Add a "this proves … / it does not …" pair only when a tier lower than the whole job was taken, and then one sentence carrying the excuse is the whole of it. No bundle id, SHA lines, or file pointers.
